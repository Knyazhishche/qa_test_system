# Руководство по использованию (Русский)

## Обзор

Этот прототип преобразует продуктовую документацию в структурированные UI-тесты с помощью Grok (через OpenRouter), хранит данные в Postgres c `pgvector`, и демонстрирует выполнение через консольный раннер. Документация подтягивается из Notion (или из встроенного примера, если Notion не настроен), разбивается на чанки, генерирует тест-кейсы, при необходимости мапит шаги на UI-элементы и выводит команды для исполнения. Локальный файл не требуется.

## Предварительные требования

- Node.js 18+ и npm.
- Ключ OpenRouter с доступом к `x-ai/grok-4.1-fast`.
- Postgres с расширением `pgvector` (для хранения и поиска похожих чанков).
- Опционально: ID страницы Notion, если хотите инжестить свою документацию.

## Настройка

1) Скопируйте шаблон окружения и задайте ключи:
```bash
cp .env.example .env
```
- Установите `OPENROUTER_API_KEY` в `.env`.
- Задайте `POSTGRES_URL` (нужен `pgvector`).
- Опционально: `NOTION_API_KEY` + `NOTION_PAGE_ID`, чтобы тянуть страницы из Notion.
- Дополнительно можно переопределить `OPENROUTER_BASE_URL`, `OPENROUTER_GROK_MODEL`, `OPENROUTER_REASONING`, `EMBEDDING_DIMENSIONS`.

2) Установите зависимости:
```bash
npm install
```

3) (Опционально) Проверка типов/сборка:
```bash
npm run build
```

## Запуск встроенных сценариев

### Демо: инжест (Notion или встроенный пример) + генерация тестов
По умолчанию берет страницу из Notion при наличии `NOTION_PAGE_ID`; иначе использует встроенный пример. Хранит данные в Postgres.
```bash
npm run demo
```
Что происходит:
- Читает страницу Notion (или встроенный текст) и дробит на чанки.
- Вычисляет детерминированные эмбеддинги (демо-вариант) и кладет чанки в Postgres+pgvector.
- Запрашивает Grok через OpenRouter строгим JSON-промптом для генерации тестов.
- Сохраняет кейсы и шаги в Postgres и выводит краткую сводку.

### Симулированный пайплайн: генерация + маппинг + консольный раннер
Полный проход с заглушечным UI-мэпом и консольным драйвером.
```bash
npm run run-simulated
```
Что происходит:
- Инжест из Notion (если настроено) или из встроенного текста, генерация тестов через Grok.
- Засевка примитивной UI-карты для `/login`.
- (Опционально) маппинг шагов на элементы UI через Grok (строгий JSON).
- Выполнение шагов консольным `PageDriver` (можно заменить на Playwright для реального браузера).

## Важные переменные окружения

- `OPENROUTER_API_KEY` (обязательно): ваш ключ OpenRouter.
- `OPENROUTER_GROK_MODEL` (опционально): по умолчанию `x-ai/grok-4.1-fast`.
- `OPENROUTER_BASE_URL` (опционально): по умолчанию `https://openrouter.ai/api/v1`.
- `OPENROUTER_REASONING` (опционально): `true`/`false`; включает/выключает флаг reasoning в запросах.
- `NOTION_API_KEY` (опционально, но обязателен для инжеста из Notion): ваш секрет интеграции Notion.
- `NOTION_PAGE_ID` (опционально): ID страницы; если не задан, используется встроенный пример.
- `NOTION_API_BASE_URL` (опционально): по умолчанию `https://api.notion.com/v1`.
- `NOTION_API_VERSION` (опционально): по умолчанию `2022-06-28`.
- `POSTGRES_URL` (обязательно): строка подключения к Postgres с `pgvector`.
- `POSTGRES_SCHEMA` (опционально): по умолчанию `public`.
- `EMBEDDING_DIMENSIONS` (опционально): по умолчанию `64`, должно совпадать с измерением vector-колонки.

## Инжест документации из Notion

1) Установите `NOTION_API_KEY` в `.env` (создайте интеграцию в Notion и поделитесь с ней страницей/базой).  
2) Запустите команду инжеста с ID страницы:
```bash
npm run notion-ingest -- <notion_page_id> [featureKey]
```
Пример:
```bash
npm run notion-ingest -- 0123456789abcdef0123456789abcdef my/feature-key
```
Что происходит:
- Тянет блоки страницы через Notion API и превращает в markdown-подобный текст.
- Делит содержимое на чанки и сохраняет как источник Notion.
- Генерирует тест-кейсы через Grok для указанного `featureKey` (по умолчанию `notion/feature`).

## Примеры

- Минимальный `.env` (подставьте свои значения):
```bash
POSTGRES_URL=postgres://user:pass@localhost:5432/qa_test_system
OPENROUTER_API_KEY=sk-...
NOTION_API_KEY=secret_...
NOTION_PAGE_ID=0123456789abcdef0123456789abcdef
```

- Генерация тестов для конкретной страницы Notion и фичи:
```bash
npm run notion-ingest -- 0123456789abcdef0123456789abcdef auth/login
```

- Демо без Notion (используется встроенный пример):
```bash
unset NOTION_PAGE_ID
npm run demo
```

- Симуляция с маппингом и консольным выводом:
```bash
npm run run-simulated
```

## Основные файлы

- `src/index.ts`: CLI с командами `demo` и `run-simulated`.
- `src/llm/openRouterClient.ts`: мини-клиент OpenRouter chat completions.
- `src/prompts/*.ts`: промпты для генерации тестов и маппинга действий.
- `src/services/ingestionService.ts`: инжест markdown + чанкинг + эмбеддинги.
- `src/services/testCaseGenerator.ts`: генерация тестов через Grok с валидацией Zod.
- `src/services/actionMapper.ts`: сопоставление шагов с элементами UI через Grok.
- `src/services/runner.ts`: консольный раннер (можно заменить `PageDriver` на Playwright).
- `src/storage/inMemoryStore.ts`: in-memory хранилище и поиск по похожести.

## Как развивать в продакшен

1) Заменить `ConsolePageDriver` на драйвер на базе Playwright (headless/headed).
2) Перейти на Postgres + pgvector вместо in-memory хранилища.
3) Строить UI-карту реальным сканированием страниц Playwright и сохранять элементы по роутам.
4) Укрепить промпты и добавить ретраи/лимиты для LLM-запросов.
5) Добавить репорты (скриншоты, трейс), а также API/CLI для запусков из CI.

## Частые проблемы

- Нет ключа: убедитесь, что `OPENROUTER_API_KEY` задан и доступен окружению, где выполняются npm-скрипты.
- Ошибки парсинга JSON: Grok должен вернуть строгий JSON; попробуйте перезапустить с меньшими чанками или упростить текст.
- Нет сгенерированных тестов: проверьте, что источник (Notion или встроенный пример) содержит релевантный текст; при необходимости скорректируйте запрос в `src/index.ts`.
